## Usage
All JBDesign System Component initial their needed variables themselves and you don't need any initialization to use our components. **But** if you need shadow variables for your own elements you can initialize them like this:

```javascript
import {defineShadows} from 'jb-core/theme';
// it will define all shadow related css variables in @property and :root you can also customize them in your css
defineShadows();
```

Components call `registerDefaultVariables()` when they are initialized, which runs `defineShadows()` beside `defineSizes()` and `defineColors()`, so shadow tokens are also available as soon as the first component of the design system is rendered on the page.

Both control tokens declare `var(--jb-shadow-sm)` as their value and `--jb-shadow-sm` itself is `none`, so the design system starts without any shadow and every design language can turn elevation on.

## how the default values resolve

the default values are declared on the root element by `defineShadows()`, and a css variable reference is resolved in the scope where it is **declared**, not where it is used. that means the control tokens pick up `--jb-shadow-sm` from the root scope, so declaring only `--jb-shadow-sm` inside a nested wrapper does not move the control shadows. to change them you either set the semantic tokens themselves, or set both the base token and the mapping in the same scope:

```css
/* recommended: set the semantic tokens where they should apply */
body {
  --jb-control-shadow: 0 0.25rem 0.75rem oklch(0% 0 0 / 0.12);
  --jb-control-shadow-focus: 0 0 0 0.1875rem oklch(60% 0.26 256 / 0.28);
}

/* or drive everything from the base variant by declaring the mapping in the same scope */
body {
  --jb-shadow-sm: 0 0.25rem 0.75rem oklch(0% 0 0 / 0.12);
  --jb-control-shadow: var(--jb-shadow-sm);
  --jb-control-shadow-focus: var(--jb-shadow-sm);
}
```

because `defineShadows()` writes these three tokens as inline values on the `html` element, a plain `:root` declaration in your stylesheet loses against them. declare your values on `body` or on any wrapper element, or make the `:root` declaration important:

```css
:root {
  --jb-shadow-sm: 0 0.25rem 0.75rem oklch(0% 0 0 / 0.12) !important;
  --jb-control-shadow: var(--jb-shadow-sm) !important;
}
```

## Live example

Shadow values are plain CSS `box-shadow` values, so any valid value works: `none`, `inset` shadows, a single shadow or multiple comma separated shadows. in the example below the wrapper declares the base token, the mapping and the focus token in the same scope, while the boxes only read the standard tokens.

<style>{`
  .jb-shadow-demo {
    /* the base shadow, usually set once in your app or design language */
    --jb-shadow-sm: 0 1px 0.125rem oklch(0% 0 0 / 0.12), 0 0.375rem 1rem oklch(0% 0 0 / 0.08);
    /* the mapping is declared in the same scope so the base token is picked up here */
    --jb-control-shadow: var(--jb-shadow-sm);
    /* an optional override for the focus state, for example a colored focus ring */
    --jb-control-shadow-focus: 0 0 0 0.1875rem oklch(60% 0.26 256 / 0.28);

## change the variables

you can easily change every css variable value like any other css variable see [this](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_cascading_variables/Using_CSS_custom_properties) to whatever value you want. shadow tokens inherit, so a declaration on any wrapper reaches the components inside it, even when a component renders its control inside a shadow root.

```css
body {
  /* style each state separately */
  --jb-control-shadow: inset 0 0 0 1px oklch(0% 0 0 / 0.06);
  --jb-control-shadow-focus: 0 0 0 0.1875rem oklch(60% 0.26 256 / 0.28);
}

/* scope a different shadow to a part of your app */
.my-panel jb-input {
  --jb-control-shadow: none;
}
```

## how components consume shadow tokens

components keep their own part variable and use the standard token as its default, so you can customize either the whole app or a single part of a component:

```css
/* inside a component stylesheet, for example jb-input variables.css */
:host {
  --box-shadow: var(--jb-control-shadow);
  --box-shadow-focus: var(--jb-control-shadow-focus, none);
}
```

the control part then applies the part variable in every state:

```css
/* inside a component stylesheet, for example jb-input.css */
.control {
  box-shadow: var(--box-shadow);
}

.control:focus-within {
  box-shadow: var(--box-shadow-focus);
}
```

`--jb-control-shadow` and `--jb-control-shadow-focus` are read by `jb-input`, `jb-textarea` and the `jb-select` listbox today (`--jb-listbox-box-shadow` and `--jb-listbox-box-shadow-focus` are the listbox level variables that fall back to them). the custom design languages documented in [Theme/Custom](?path=/docs/theme-custom-default--docs) define their elevation with the same tokens, for example the Aurora style:

```css
jb-input.aurora-style {
  --jb-control-shadow: inset 0 0 0 1px oklch(100% 0 0 / 0.04);
  --jb-control-shadow-focus: 0 0 0 0.1875rem oklch(83% 0.11 185 / 0.18);
}
```

## notes

- shadow tokens are registered in `@property` with the universal `*` syntax because CSS has no syntax for shadow values in `@property` yet, therefore the browser does not validate or animate them. make sure you always provide a real `box-shadow` value.
- the base token defaults to `none` because the design system does not force any elevation on your app.
- `--jb-shadow-sm` only changes the elements that read it directly. the control tokens resolve it in the scope where they are declared, so re-declare the mapping in your scope when you want the base variant to drive them.
- only one elevation variant (`--jb-shadow-sm`) is part of the standard tokens today. components read the semantic tokens, so adding a new elevation variant later only needs a change in the semantic token mapping.
- the rest of the standard values are documented in [Theme/Sizes](?path=/docs/theme-sizes--docs), [Theme/Colors](?path=/docs/theme-colors--docs) and [Theme/Other Tokens](?path=/docs/theme-other-tokens--docs).
